# 字幕节奏修复（SRT Rhythm Fix）

在浏览器内修复 SRT 字幕的**断句**与**毫秒时间边界**：保持文字内容与顺序不变、保持选区首条开始时间与末条结束时间不变，在「每秒字符数 / 单行字数 / 最小提示间隔」三组限制下，求**边界总移动量最小**的可行方案；无解时逐条列出冲突规则。支持**锚点锁定**：可分别锁定某条字幕的文字归属、开始时间或结束时间，求解器在严格保持锁定项的前提下联合调整其余断句与时间边界。

另内置独立的**术语检查**模块：导入简体中文术语表（标准词、别名、大小写敏感选项）即可扫描整部 SRT，找出别名、错误大小写与常见同音误写，显示条目序号、原词、建议词与命中次数；支持按术语/处理方式/关键词筛选，点击命中跳转并高亮对应字幕；可一键生成**仅包含替换预览的 JSON**——绝不直接改写原字幕，也不影响当前节奏修复选区。遇到术语冲突（同一别名指向多个标准词、或同一位置命中多个术语）时保留原文并标记需人工确认。

所有数据仅保存在浏览器本地，不上传任何服务器。

技术栈：**React 18 + TypeScript + Vite**，纯前端、无后端。

## 一键启动

### 方式一：Docker Compose（推荐，生产构建）

```bash
docker compose up --build -d
```

然后打开：

- **地址**：http://localhost:**8080**
- 端口可改：`PORT=9000 docker compose up --build -d`

停止：`docker compose down`

### 方式二：Docker Compose（开发模式，带热更新）

```bash
docker compose -f docker-compose.dev.yml up
```

然后打开：

- **地址**：http://localhost:**5173**（Vite dev server）
- 端口可改：`DEV_PORT=3000 docker compose -f docker-compose.dev.yml up`

### 方式三：本地 Node（需 Node.js 20+）

```bash
npm install
npm run dev        # 开发：http://localhost:5173
npm run build && npm run preview   # 生产预览：http://localhost:4173
```

## 使用步骤

1. **导入 SRT**：选择本地 `.srt` 文件（兼容 BOM / CRLF / 逗号或点毫秒），或点击「载入示例」。
2. **选取字幕**：在列表中点击，选择**至多 30 条连续字幕**（再次点击端部条目可收缩选区）。
3. **（可选）锚点锁定**：选区内每行右侧的「文 / 始 / 终」三个按钮分别锁定该条的——
   - **文**：文字归属（该条文字保持原样，不参与跨条断句调整）；
   - **始**：开始时间（该条开始边界保持原值）；
   - **终**：结束时间（该条结束边界保持原值）。

   再次点击取消锁定。锁定项在求解与导出时**严格保持原值**；修改选区或参数后锁定仍然保留（仅选区内的锁定参与求解，选区外的锁定以暗色标记显示、不生效），重新导入字幕后自动清空，也可点「清除全部锁定」一键解除。
4. **设置参数**：
   - **每秒字符数（CPS）**：每条字幕时长 ≥ `1000 × 字数 ÷ CPS`（节奏下限，默认 17）；
   - **单行字数**：词感知折行后的每行最大字符数（中日韩文字可逐字断行，拉丁词不拆词，默认 18）；
   - **最小提示间隔**：相邻两条字幕之间的最小间隔毫秒数（默认 120ms）；
   - 每条字幕固定最多 2 行（标准字幕规范）。
5. **求解与比对**：点击「求最小移动方案」，左右并排展示**原稿**与**结果**——
   - 黄色底纹：跨条移动的文字；
   - 蓝色标签：该开始/结束边界移动的毫秒数；
   - 🔒 标记：锚点锁定项（原稿列与结果列均标注，锁定边界显示「🔒锁定」而非移动量）；
   - 顶部汇总：时间边界总移动量、文字移动量、移动字符数。
6. **确认导出**：点击「确认并导出 fixed.srt」下载完整 SRT（选区替换为修复结果、选区外原样保留、序号重排；**锁定项严格保持原文字与原时间**，导出前会再次校验，违反锁定即中止）。

若约束下无解，页面会列出**每一条冲突规则**及数值依据：若是锚点相互冲突（如两条相邻字幕分别锁定了结束与开始时间、间隔不足，或锁定起止的时长放不下锁定文字），会**明确指出冲突的锚点（第几条的开始/结束/文字）以及最小所需时长或间隔**，按提示解除对应锁定、调整锁定时间或放宽参数即可恢复可解。

## 术语检查（独立模块，只读不改写）

在第 2 步字幕列表下方提供，扫描**整部 SRT**，与节奏修复的选区/锁定/求解完全隔离：不修改任何字幕文本，也不会改动当前选区。

### 1. 导入简体中文术语表

支持两种格式，可点「下载 JSON 模板 / CSV 模板」获取样例：

**JSON**（数组或 `{"terms":[...]}`，字段名中英文均可）：

```json
{
  "terms": [
    { "standard": "人工智能", "aliases": ["AI技术", "AI 技术"], "caseSensitive": false },
    { "standard": "USB", "aliases": ["usb"], "caseSensitive": true }
  ]
}
```

**CSV / TSV**（首行可为表头；多个别名用 `|`、`、`、逗号或分号分隔；第 3 列为大小写开关 `true/false`、`是/否`）：

```csv
标准词,别名,大小写敏感
人工智能,AI技术|AI 技术,false
USB,usb,true
```

- **标准词**：规范写法；标准词本身的正确写法不会被当作命中。
- **别名**：误写 / 旧称 / 异体写法，命中即建议改为标准词。
- **大小写敏感**：仅对拉丁词生效。开启后标准词的错误大小写（如标准词 `USB` 出现 `Usb`）也算命中；拉丁词自动做词边界检查（`USB` 不会误命中 `USBX`）。中文词不做边界限制。
- 重复标准词自动合并别名；跳过的异常行会在页面顶部给出解析提示。

另提供**内置常见同音 / 近音误写词库**（约 60 组高置信度成词对照，如 `渡假村→度假村`、`苍海桑田→沧海桑田`、`走头无路→走投无路`），可一键开关。用户术语表中出现的字面值会**优先于**内置词库（同名对照被抑制），用户命名决策永远优先。

### 2. 扫描结果

结果表逐行给出：**条目序号（术语表序号）、术语来源（导入/内置同音）、原词（实际命中）、建议词（标准词）、处理方式、命中次数**；展开单行可看每条命中的字幕序号、行号与行内位置。

三种处理方式：

| 处理方式 | 含义 |
| --- | --- |
| **可自动替换**（绿） | 导入术语表的别名 / 错误大小写命中 |
| **需人工确认**（黄） | 内置同音误写建议，不自动替换 |
| **术语冲突**（红） | 同一别名指向多个标准词，或同一位置被多个术语命中（匹配重叠）；**保留原文** |

筛选能力：按术语（全部 / 仅导入 / 仅内置 / 指定术语）、按处理方式、按原词或建议词关键词搜索。

### 3. 点击命中跳转并高亮

点击每行右侧的「第 N 条」（或展开后的具体行内位置），页面会平滑滚动到第 2 步字幕列表对应条目，并用红色底纹高亮出该行中命中的字符；再次选择/导入字幕或术语表后自动清除高亮。

### 4. 生成替换预览 JSON

点「生成替换预览 JSON」下载 `term-replacement-preview.json`。它**只是预览**：原 SRT 与节奏修复选区均不发生任何变化。文件结构：

```json
{
  "kind": "srt-term-replacement-preview",
  "version": 1,
  "summary": {
    "cuesTotal": 128,
    "cuesWithHits": 9,
    "totalHits": 14,
    "autoReplacements": 7,
    "reviewItems": 5,
    "conflictItems": 2
  },
  "cues": [
    {
      "cueIndex": 5,
      "startMs": 11240,
      "endMs": 13200,
      "originalText": "这一讲介绍3D模型的流程",
      "previewLines": ["这一讲介绍3D模型的流程"],
      "replacements": [
        { "termIndex": 4, "term": "3D建模", "from": "3D模型", "to": "3D建模",
          "line": 1, "start": 5, "end": 9, "source": "alias",
          "mode": "conflict", "reason": "别名同时指向多个标准词：3D建模 / 三维模型" }
      ]
    }
  ],
  "note": "本文件仅为替换预览，未改写原始 SRT……"
}
```

- `mode=auto`：已写入 `previewLines` 的逐行预览（同一条字幕内多个替换基于原始码点偏移倒序应用，互不干扰）；
- `mode=review`（内置同音建议）与 `mode=conflict`（术语冲突）：**只在 `replacements` 中描述，`previewLines` 保留原文**，由人工确认后再决定是否采用。

快速体验：导入任意 SRT 后点「载入术语演示（字幕+术语表）」，演示数据覆盖自动替换、错误大小写、内置同音与术语冲突全部场景。

## 求解原理（摘要）

- **时间优化（精确全局最优）**：给定断句后，所有边界约束可变换为一条非减变量链，目标 `Σ|新边界 − 原边界|` 是标准 **L1 保序回归（Isotonic Regression）**，用 **PAVA（Pool Adjacent Violators）+ 加权中位数**精确求解；选区首/末边界与**锁定的时间锚点**均以极大权重钉死，钉死点被合并即判定该断句下锚点约束不可同时满足。
- **断句优化（该时间方案下精确最优）**：在分层 DAG 上做密集数组 DP，词典序最小化 `(时长缺口, 文字移动量)`，段合法性（非空、2 行折行、行长）带缓存；**锁定的文字归属等价于固定对应切点**，DP 只在自由切点上转移。
- **锚点预检（无解时定位冲突）**：求解前对相邻钉死点（含首末边界与全部锁定锚点）逐一做区间可行性检查——区间可用时间必须 ≥ 区间最小时长（被固定切点夹住的文字量确定，取 `⌈1000·字数 ÷ CPS⌉` 下界）+ 区间间隔需求；同时检查锁定文字的折行行数与锁定区段容量。任一不满足即直接报告冲突锚点与最小所需时长/间隔，不再返回通用失败。
- **联合优化（非凸组合问题）**：以 3 组结构化切点（均匀 / 按原字数 / 按原时长）+ 上百组随机合法切点为起点交替迭代到不动点，再做模拟退火（单/双切点扰动，**固定切点不参与扰动**）与确定性双邻域精修（单/双切点 ±3 直接评估原始时间目标），取其中移动量最小的方案。两个子问题均为精确解，联合层为高质量启发式（固定随机种子、结果可复现；30 条规模约 3 秒）。
- **验证**：`npm test` 包含 1100+ 项断言，其中时间优化器（含随机锚点锁定）在 120 个随机案例上与整数坐标暴力 DP 完全一致；小规模（≤4 条）联合求解（含随机文字/时间锁定）与“枚举全部断句 × 每案最优时间”的全局最优逐一对照；另有锚点可行、锚点冲突（间隔不足 / 时长不足 / 锁定文字超行）及解除锁定后恢复可解的场景测试。术语检查另有 60 项断言，覆盖 JSON/CSV 解析、别名与大小写匹配、拉丁词边界、码点偏移（含 emoji）、共享别名与位置重叠冲突、内置同音词抑制、替换预览只应用 auto 且保留 review/conflict 原文等。

## 配置一览

| 配置 | 默认值 | 位置 / 方式 |
| --- | --- | --- |
| 生产端口 | `8080` | `docker compose` 环境变量 `PORT` |
| 开发端口 | `5173` | `docker-compose.dev.yml` 环境变量 `DEV_PORT`，或 `vite.config.ts` |
| CPS 上限 | 17 | 页面参数区 |
| 单行字数 | 18 | 页面参数区 |
| 最小间隔 | 120 ms | 页面参数区 |
| 锚点锁定 | 无 | 选区列表每行「文 / 始 / 终」按钮（随 `localStorage` 记住，重新导入字幕后清空） |
| 选区条数上限 | 30 | 页面逻辑（`MAX_SELECTION`） |
| 每屏行数上限 | 2 | 求解器常量（`MAX_LINES`） |
| 术语表 | 无（可选导入 JSON/CSV/TSV） | 术语检查面板，随 `localStorage` 记住，可随时清除 |
| 内置同音误写词库 | 开启（约 60 组对照） | 术语检查面板勾选框（随 `localStorage` 记住） |

参数、锚点锁定与术语表都会随浏览器 `localStorage` 记住；导入的 SRT 原文同样仅存于 `localStorage`，可在页面上「清空」（会一并移除术语表）。
